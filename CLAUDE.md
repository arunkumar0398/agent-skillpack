# Agent Skillpack — Agent Context

## What This Repo Is

A universal AI agent skill repository providing 70+ reusable engineering skills, auto-adapted to 8 coding agent formats (OpenCode, Claude Code, Codex, Cursor, Windsurf, GitHub Copilot, Cline, Aider).

## Directory Structure

```
skills/           → Canonical skills (source of truth, OpenCode SKILL.md format)
skills/_template/ → Template for new skills
dist/             → Generated adapters (DO NOT EDIT — rebuilt by build.js)
build.js          → Adapter generator: converts skills/ to all 8 agent formats
validate.js       → Schema validator: checks SKILL.md frontmatter + meta.json
generate-meta.js  → Auto-generates meta.json for skills missing it
```

## Commands

```bash
node build.js          # Regenerate all 8 adapter sets in dist/
node validate.js       # Validate all skills (frontmatter + meta.json)
node generate-meta.js  # Auto-generate meta.json for skills missing it
npm run build          # Same as node build.js
npm run validate       # Same as node validate.js
```

## Adding a New Skill

1. Create `skills/<kebab-case-name>/SKILL.md`
2. Create `skills/<kebab-case-name>/meta.json`
3. Run `node generate-meta.js` if you skipped meta.json
4. Run `node build.js` to regenerate adapters
5. Run `node validate.js` to verify

## SKILL.md Anatomy

Every skill MUST follow this structure:

```markdown
---
name: skill-name
description: >-
  One-line description. Use when [trigger].
version: 1.0.0
tags: [category1, category2]
agents: [opencode, claude, codex, cursor, windsurf, copilot, cline, aider]
---

# Skill Name

## Overview
## When to Use
## Process
### Step 1: ...
### Step 2: ...
## Common Rationalizations
## Red Flags
## Verification
```

## meta.json Format

```json
{
  "name": "skill-name",
  "version": "1.0.0",
  "description": "One-line description",
  "tags": ["tag1", "tag2"],
  "agents": ["opencode", "claude", "codex", "cursor", "windsurf", "copilot", "cline", "aider"],
  "category": "architecture|workflow|operations|security|quality",
  "dependencies": [],
  "scripts": [],
  "references": []
}
```

## Key Rules

- Skills are markdown-first — no code dependencies unless truly needed
- Every skill needs both `SKILL.md` and `meta.json`
- The `Process` section must have numbered steps with concrete actions
- `Common Rationalizations` must have a table of excuses vs reality
- `Verification` must have a checklist of specific checks
- Never edit `dist/` directly — it's regenerated by `build.js`
